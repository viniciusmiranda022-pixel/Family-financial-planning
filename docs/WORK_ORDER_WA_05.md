# Work Order — WA-05 Conversational Context (#77)

## Objective
Implement short, structured conversational continuity for financial follow-ups. Context may help the LLM resolve references, but Family Finance remains the sole source of financial truth and authorization.

## Scope
- Context keyed server-side by household + authorized user + conversation; never accept household/identity from LLM context.
- Persist only minimal structured state needed for continuity: prior typed tool/action intent, canonical filters/entities, period, metric, grouping and safe result references; no chain-of-thought.
- Support generic follow-ups such as `e mês passado?`, `qual a diferença?`, `e a Kelly?`, `e se tirar mercado?`, `mostra por mês` and the acceptance sequence in #77 without phrase-specific routing.
- Define bounded TTL, maximum context size/history and deterministic cleanup/expiry behavior.
- On material ambiguity or stale/insufficient context, return clarification rather than silently assuming.
- Context must never grant permission, change household, bypass RBAC, confirm a write, or turn an LLM hypothesis into fact.
- Reuse WA-04 generic typed tools and canonical backend calculations; no second financial engine and no SQL generated by the LLM.
- Process restart/retry/redelivery must not duplicate financial operations; preserve WA-03 idempotency/audit/undo semantics.

## Acceptance criteria
- The full #77 follow-up sequence resolves through structured context + backend tools, with financial values recalculated by Family Finance.
- Novel equivalent follow-ups work without adding phrase handlers.
- Explicit new user information overrides only the named contextual dimension; unrelated safe constraints are retained when unambiguous.
- Ambiguous pronouns/entities/periods/metrics fail to clarification without mutation.
- Context expiration/reset cannot leak or resurrect stale authority or pending confirmation.
- Vinicius/Kelly may have separate conversation state inside the same household; different households are strictly isolated.

## Mandatory tests
- #77 four-turn sequence end-to-end, plus `e a Kelly?`, `e se tirar mercado?`, `mostra por mês` and unseen paraphrases.
- User/household/conversation isolation, including colliding conversation IDs and holder names.
- TTL expiry, size/history bounds, cleanup, process restart and replay/redelivery.
- Ambiguous/stale context returns clarification and performs no write.
- Context cannot confirm/cancel/undo or select household by itself; write confirmation remains explicit and authorized.
- Prompt-injection/tool-schema fail-closed behavior with malicious prior context.
- Exact parity with WA-04/canonical calculations, regression suite, lint, PostgreSQL integration for persistence/concurrency semantics, Alembic migration safety if schema changes, and all applicable GitHub Actions.

## Risks / review gates
Review privacy/PII, context poisoning, stale references, authorization confusion, race conditions between simultaneous messages, optimistic/row locking where needed, migration/backfill compatibility, deterministic timestamps/timezone, retention/cleanup indexes, auditability, and restart safety.

## Prohibitions
- No static catalog of follow-up phrases or hardcoded acceptance sequence.
- No chain-of-thought persistence, raw prompt transcript retention beyond already-authorized audit requirements, or unbounded context.
- No financial arithmetic in the LLM, free SQL, arbitrary ORM expressions, or second financial engine.
- No authority/household/write-confirmation derived from conversation memory.
- Do not broaden into WA-06+, Oracle/OCI (#59–65), or unrelated backlog.
- Claude must not merge.

## Execution
Claude implements on this branch/PR, documents migrations/rollback and any Technical Challenge with evidence, and runs all applicable tests. Integration authority reviews and merges only with stable head, green applicable CI, safe data compatibility and all criteria satisfied.
